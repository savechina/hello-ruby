# 简介

## 为什么学习 Ruby？

Ruby 是一门由松本行弘（Matz）在 1995 年发布的编程语言。它的设计哲学不是追求极致的性能，也不是追求最小的语法，而是追求程序员的幸福感。Matz 曾经说过：

> 人们总关注效率、是否能处理更多信息。我关注的是人们是否快乐。

这句话总结了 Ruby 为什么存在。Ruby 的语法简洁到接近自然语言，它的标准库丰富到几乎覆盖所有常见需求，它的社区强调约定优于配置。学 Ruby 不只是学一门语言，更是学习一种"让工具服务于人"的价值观。

## Ruby 3.2+ 值得注意的新特性

Ruby 3.2 在 2023 年底发布，带来了不少实用的改进。

**Ractor 逐渐成熟。** Ruby 3.0 引入了 Ractor，一种基于 Actor 模型的真正并行原语。到 3.2 版，Ractor 的 API 更加稳定，你可以在不受 GVL（全局虚拟机锁）限制的情况下并发执行 CPU 密集型任务。每个 Ractor 拥有独立的内存空间，通过消息传递通信，从根本上避免了竞态条件。

**模式匹配优化。** Ruby 2.7 引入的 `case/in` 模式匹配语法在后续版本中不断优化。你可以匹配数组结构、哈希结构，甚至自定义类的内部状态。这对于处理嵌套数据（比如 JSON 解析结果）非常有用。

**JIT 实验性增强。** Ruby 3.0 添加了 JIT 编译器，3.2 继续优化。虽然 JIT 还没有达到生产可用的稳定程度，但对于某些纯计算型场景已经能看到可观的性能提升。

除此之外，3.2 还改进了标准库的性能、增加了 `Hash#except`、`Enumerator::Lazy#eager` 等实用方法、改进了错误信息的可读性。

## Ruby 与其他语言对比

如果你已经会其他编程语言，理解 Ruby 与其他语言的区别会加速你的学习。

**Ruby vs Python。** 两者都是动态类型、高级语言。Python 强调"一种明确的方式"（Zen of Python），Ruby 强调"允许程序员自由选择"。Python 用缩进定义块，Ruby 用 `do/end` 或 `{}`。Python 标准库大而全，Ruby 用 gem 生态弥补。如果你在两者之间犹豫，Ruby 的元编程能力和 Rails 生态是独特优势。

**Ruby vs JavaScript。** 两者都有"一切皆是对象"的理念。Ruby 的块（block）、Proc、Lambda 与 JavaScript 的闭包概念相似但更优雅。Ruby 没有原型链，使用传统的类和模块混入。前端开发选 JavaScript，后端和脚本工具选 Ruby，各有专攻。

**Ruby vs Rust。** Rust 强调内存安全和零成本抽象，编译时检查一切。Ruby 在运行时做检查，追求开发速度。两者互补：Ruby 适合快速验证想法，Rust 适合对性能和安全性有严格要求的场景。

## 项目组织方式

Hello Ruby 采用三层结构，每层解决不同的学习阶段需求。

**Basic 层** 的 15 个主题覆盖 Ruby 基本语法。每个主题独立成模块，通过 `hello basic 主题名` 运行。配套文档在 `docs/src/basic/` 下，用 mdBook 格式编写，每个概念从简单到复杂逐步展开。

**Advance 层** 的 10 个主题深入 Ruby 高级特性。这些内容不再是语法层面的介绍，而是带你理解 Ruby 的设计思想。比如元编程一章不只是教你 `define_method` 的用法，更让你理解 Ruby 运行时一切都是对象这个核心概念。配套文档在 `docs/src/advance/` 下。

**Awesome 层** 是生产级实战。这一层使用 dry-system、Rails、Sidekiq 等行业标准工具，展示如何从零搭建一个可部署的服务。这不是玩具代码，是可以直接用于实际项目的参考架构。

配套文档通过 mdBook 组织，`SUMMARY.md` 定义目录结构，每个 `.md` 文件对应一个章节。你可以在本地运行 `mdbook serve` 查看效果，也可以在 GitHub Pages 上在线查看。

## 阅读建议

如果你完全没有编程经验，请从 Basic 层的变量章节开始，按顺序读完 15 个主题。每个章节的代码都可以直接运行，建议你跟着动手敲一遍。

如果你有其他语言经验，Basic 层可以快速浏览，重点看 Ruby 与其他语言不同的部分：块与 Proc、模块混入、符号（Symbol）、元编程。Advance 层是精华所在，尤其是元编程和并发模型这两章。

如果你已经是中高级开发者想学习 Ruby 生态，可以直接从 Advance 层的 dry-system 和测试章节入手，然后跳到 Awesome 层看完整的架构设计。

不管你处在哪个阶段，建议你同时阅读文档和运行代码。文档帮你理解"为什么"，代码帮你验证"怎么做"。两者结合学习效果最好。
